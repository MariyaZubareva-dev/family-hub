# Тестовый стенд Family Hub

Основа: `feature/personal-savings`, коммит `f146cdd611ebc931f8e321b77408d5872dc3bf56`.
Изменения стенда находятся в ветке `feature/qa-stand`.

Это настоящее приложение с Laravel и PostgreSQL, без подмены ответов API.
Стенд предназначен для проверки интерфейса, операций и прав доступа на вымышленных данных.

## Запуск

Нужны Docker Engine / Docker Desktop, Compose v2 с поддержкой `up --wait`, Git, Bash, OpenSSL и curl.
Используйте отдельный каталог. Не копируйте `.env.production`, базу, чеки или ключи рабочего приложения.

```bash
git clone --branch feature/qa-stand --single-branch https://github.com/MariyaZubareva-dev/family-hub.git family-hub-qa
cd family-hub-qa
bash scripts/qa.sh up
```

Скрипт создаст `.env.qa` с отдельными случайными ключами и правами доступа 600,
соберёт образы, применит миграции, создаст тестовую семью и выполнит проверки API.
Файл `.env.qa` исключён из Git. При повторном запуске он сохраняется.

Открыть: `http://localhost:18080`. Вверху страницы есть переключатель пользователей.
При переключении страница перезагружается, несохранённые формы теряются.
Для двух одновременных сессий используйте разные профили браузера или обычное и приватное окно:
вкладки одного профиля разделяют localStorage и не являются независимыми пользователями.

Если запускаете на VPS, выполните clone в отдельный каталог, например `/opt/family-hub-qa`.
На своём компьютере откройте SSH-туннель, подставив существующие SSH-логин и адрес сервера:

```bash
ssh -N -L 18080:127.0.0.1:18080 USER@SERVER
```

После этого откройте тот же `http://localhost:18080` на своём компьютере.
Не публикуйте этот порт напрямую: тестовый вход позволяет выбирать аккаунт без пароля.
SSH-туннель на компьютере Марии не открывает доступ облачному браузеру помощника.
Для совместной удалённой проверки нужен отдельный защищённый адрес; он в этой конфигурации не создаётся.

## Начальное состояние

| Пользователь | Тестовый ID | Роль | Доход | Личная копилка |
| --- | --- | --- | --- | --- |
| Анна (тест) | 999001 | Администратор | 100 000 ₽ | «Отпуск Анны»: 10 000 ₽ |
| Борис (тест) | 999002 | Участник | 60 000 ₽ | «Велосипед Бориса»: 7 000 ₽ |

Есть расход 5 000 ₽. Копилки пополнены из бюджета, поэтому доступно семье:
`100 000 + 60 000 − 5 000 − 10 000 − 7 000 = 138 000 ₽`.
Каждому пользователю должна возвращаться только его копилка. Общая история переводов
не должна содержать названий копилок, их идентификаторов и личных заметок.
Есть событие и напоминание на следующий день после первого запуска, а также тестовый список.
Сидирование выполняется в транзакции только при первом запуске; перезапуск не восстанавливает удалённые записи.

## Управление

```bash
bash scripts/qa.sh status
bash scripts/qa.sh check
bash scripts/qa.sh logs
bash scripts/qa.sh down
```

`down` останавливает только проект `family-hub-qa`, сохраняя тестовые данные.
Повторный `up` запускает стенд с теми же данными. Автоматического удаления томов нет.
Изменение ролей или удаление участников в процессе проверки может закономерно привести к ошибке
повторного smoke-теста: он ожидает двух активных участников с исходными ролями.

## Изоляция и ограничения

- Отдельные Compose-проект, сеть, PostgreSQL и тома `qa_pgdata`, `qa_storage` с префиксом проекта.
- Нет фиксированных имён контейнеров, подключений к production-томам и опубликованных портов базы/API.
- Веб-порт привязан только к `127.0.0.1:18080`. Nginx отправляет API-запросы в backend этого стенда.
- Серверный dev-вход использует существующее ограничение `APP_ENV=local`; production middleware не меняется.
- Переключатель включается только при сборке с `VITE_QA_STAND=true`; обычная сборка его не содержит.
- Telegram, OpenAI и внешнее распознавание чеков не настроены. Очередь и планировщик не запущены.
  Доставку уведомлений, фоновую обработку и внешнее распознавание этим стендом подтвердить нельзя.
- Ключи и данные production не используются. Резервная копия рабочего приложения для запуска стенда не нужна.

## Проверки подготовки

В среде подготовки выполнены сборки обычного и тестового frontend, проверка синтаксиса Bash,
разбор YAML и проверки конфигурации изоляции. Полный Docker-запуск, миграции и PHP smoke-тест
не выполнены: в этой среде нет Docker и PHP. Скрипт `up` выполнит runtime-проверки на машине запуска;
не считать стенд работающим до его успешного завершения.

Smoke-тест проверяет health, отказ без пользовательского заголовка и для неизвестного ID,
роли двух участников, принадлежность возвращаемых копилок, совпадение общего доступного остатка
и отсутствие личных полей в общей истории. Он не заменяет проверку изменения чужой копилки,
полный пользовательский аудит или проверку на двух реальных Telegram-аккаунтах.
