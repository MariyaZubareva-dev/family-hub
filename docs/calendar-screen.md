# Календарь

Оформление следует interface-style.md. Сетка месяца — семь колонок, компактные ячейки с отметками планов. Навигация: предыдущий/следующий месяц, «Сегодня», выбор дня и «Весь месяц». Выбранный день и текущая дата различаются; даты — кнопки, доступные с клавиатуры.

Список показывает запланированные события и напоминания выбранного месяца или дня. Названия переносятся, длинные описания раскрываются отдельно. Указаны тип, время и ответственный. Пустое состояние и загрузка не смешиваются.

Событие и напоминание создаются через общий Modal из Финансов. Поля даты и времени разделены, чтобы помещаться на телефоне. Событие длится один час, участники — все члены семьи. В событии и напоминании можно выбрать одного или нескольких ответственных флажками. Пустой выбор не сохраняется. Все выбранные имена отображаются в списке планов. Пояснение доступно через кнопку «О календаре». Часовой пояс соответствует устройству, даты отправляются в API как ISO UTC. После сохранения открывается день созданного плана и показывается подтверждение. Во время отправки повторное сохранение и закрытие отключены; при ошибке введённые данные сохраняются.

API принимает responsible_member_ids — массив уникальных идентификаторов активных участников своей семьи. Старый responsible_member_id также принимается и возвращается как первый элемент для совместимости. PATCH заменяет список целиком; изменение остальных полей сохраняет назначения. Миграция 000025 переносит старого ответственного в массив. При изменении списка напоминания сбрасывается notification_sent_at, как при изменении одного ответственного. Рассылка остаётся общей для активных участников с доступом к календарю. Обновляются backend, queue, scheduler и frontend; требуется migrate --force. Проверяются создание и повторная загрузка обоих типов планов, выбор дат/месяца, сохранение черновика при ошибке, возврат фокуса, ширины 320/393/768 px и короткий экран 320×480.
