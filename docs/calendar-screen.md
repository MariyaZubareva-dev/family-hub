# Календарь

Оформление следует interface-style.md. По умолчанию показана одна неделя, весь месяц раскрывается кнопкой. Фильтры «Все», «Встречи», «Напоминания» разделяют планы. Сетка — семь колонок, компактные ячейки с отметками планов. Навигация: предыдущий/следующий месяц, «Сегодня», выбор дня и «Весь месяц». Выбранный день и текущая дата различаются; даты — кнопки, доступные с клавиатуры.

Список показывает запланированные события и напоминания выбранного месяца или дня. Названия переносятся, длинные описания раскрываются отдельно. Указаны тип, время и ответственный. Пустое состояние и загрузка не смешиваются.

Событие и напоминание создаются через общий Modal из Финансов. Поля даты и времени разделены, чтобы помещаться на телефоне. Событие длится один час, участники — все члены семьи. В событии и напоминании можно выбрать одного или нескольких ответственных флажками. Пустой выбор не сохраняется. Все выбранные имена отображаются в списке планов. Пояснение доступно через кнопку «О календаре». Часовой пояс задаёт администратор в «Семье», по умолчанию Europe/Moscow. Ввод и отображение календаря используют этот пояс, независимо от устройства; даты отправляются в API как ISO UTC. Несуществующее время при переходе на летнее время отклоняется. Смена пояса семьи не сдвигает сохранённые моменты времени. Текст уведомления использует пояс самой записи. После сохранения открывается день созданного плана и показывается подтверждение. Во время отправки повторное сохранение и закрытие отключены; при ошибке введённые данные сохраняются.

API принимает responsible_member_ids — массив уникальных идентификаторов активных участников своей семьи. Старый responsible_member_id также принимается и возвращается как первый элемент для совместимости. PATCH заменяет список целиком; изменение остальных полей сохраняет назначения. Миграция 000025 переносит старого ответственного в массив, 000026 добавляет пояс семьи с Москвой по умолчанию. При изменении списка напоминания сбрасывается notification_sent_at, как при изменении одного ответственного. Рассылка остаётся общей для активных участников с доступом к календарю. API создания напоминания возвращает status=SCHEDULED сразу после сохранения, включая значения по умолчанию из базы. Оповещения содержат inline-кнопку web_app для запуска нужного раздела мини-приложения вместо текстовой ссылки на сайт. Старые уже отправленные сообщения не меняются. Обновляются backend, queue, scheduler и frontend; требуется migrate --force. Проверяются создание и повторная загрузка обоих типов планов, выбор дат/месяца, сохранение черновика при ошибке, возврат фокуса, ширины 320/393/768 px и короткий экран 320×480.


## Действия с напоминаниями

В календаре у напоминания есть чекбокс выполнения, кнопки редактирования и удаления. Изменяются название, описание, дата, время и ответственные. Очистка описания отправляет `null`. Дата редактируется в текущем часовом поясе семьи. Ошибка сохраняет черновик; состояние списка меняется только после успешного ответа сервера. Удаление требует подтверждения и удаляет запись у всей семьи без возможности восстановления.

Выполненные напоминания не входят в активные планы и счётчики дней. Они доступны в сворачиваемом блоке «Выполнено» с теми же фильтрами месяца и дня; снятие отметки возвращает напоминание в планы. Просроченные активные напоминания помечены текстом «Просрочено». На главной напоминание можно выполнить чекбоксом и отменить последнее выполнение; после перезагрузки вернуть его можно из календаря.

API использует существующие `PATCH /api/v1/reminders/{id}` и `DELETE /api/v1/reminders/{id}`. Ответы GET/POST/PATCH содержат `can_edit` и `can_complete`. Автор и администратор могут менять и удалять запись. Назначенный ответственный также может отправлять PATCH только со статусом `COMPLETED` или `SCHEDULED`; менять текст, дату и назначение или удалять чужую запись он не может. Остальные участники имеют доступ только на чтение. Изоляция семей и доступ к разделу проверяются сервером.

Очередь перед отправкой проверяет существование напоминания, активный статус, дату и версию уведомления. Изменение даты, ответственных или статуса увеличивает `notification_revision`; задания от прежней версии пропускаются. Текст сообщения берётся из актуальной записи. Возврат будущего напоминания в планы восстанавливает недоставленные уведомления. Уже доставленное уведомление на ту же дату и время одному участнику повторно не отправляется. Уже доставленные сообщения Telegram не удаляются. Повторяющиеся напоминания и отдельные списки задач этой доработкой не добавляются.

Миграция `2026_10_29_000034_add_reminder_notification_revision` добавляет служебную версию с начальным значением 0. При выкладке обновить backend, очередь, scheduler и frontend, выполнить миграцию до запуска новых контейнеров. Старые задания версии 0 остаются совместимыми, пока напоминание не изменено.
