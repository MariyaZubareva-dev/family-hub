# Модель расчёта кредита Family Hub

## Источник договорных условий

Family Hub поддерживает два уровня данных: исходные параметры кредита и договорный график платежей. Для кредитов, где сумма регулярного платежа меняется по ходу срока, используется `payment_schedule`, а не обратный расчёт срока из одного платежа.

`payment_schedule` содержит непрерывные периоды вида:

```text
from_month → to_month → amount
```

Периоды должны покрывать весь срок кредита без пропусков и перекрытий.

## Начисление процентов

Для каждого платёжного периода проценты считаются по фактическому количеству календарных дней. Стартовая дата периода не включается, дата платежа включается. При переходе через 1 января знаменатель меняется с 365 на 366 для високосного года.

Эквивалентная формула для участка внутри одного года:

`interest = balance × annual_rate × days / days_in_year`

Если период пересекает Новый год, сумма состоит из двух или более таких участков.

Эта модель воспроизводит первые строки предоставленного договорного графика: первый платёж целиком состоит из процентов, а на следующем платеже начинается погашение тела. При проверке исходного PDF отдельные строки могут отличаться на 1 копейку из-за внутренней точности/округления банковской системы; приложение не подгоняет формулу под конкретную копейку.

## Договорный платёж

Если в договоре размер платежа меняется по периодам, каждая строка графика использует свою сумму. Последний платёж также может отличаться от предыдущего периода.

Таким образом, исходная дата окончания определяется только `first_payment_date` и `term_months`:

`original_end = first_payment_date + (term_months - 1) месяцев`.

Размер `standard_payment` не используется для определения исходного срока, если задан `payment_schedule`.

## Исторические обычные платежи

Все регулярные платежи с датой не позже текущей даты считаются проведёнными по договорному графику. Пользователь не обязан вручную вводить каждый обычный платёж. Отдельно сохраняются только фактические досрочные платежи.

Это позволяет восстановить состояние кредита на текущую дату из: суммы кредита, ставки, договорного графика и истории досрочек.

## Досрочное погашение в день регулярного платежа

Сначала проводится обычный платёж: начисленные проценты → тело. После этого сумма досрочного платежа полностью уменьшает основной долг, если нет непогашенных процентов.

## Досрочное погашение после регулярной даты

После очередного платежа проценты продолжают начисляться до фактической даты досрочного платежа. Из суммы досрочки сначала погашаются начисленные к этой дате проценты, затем оставшаяся сумма уменьшает тело.

Если в одном платёжном периоде несколько досрочных операций, они обрабатываются по хронологии. После каждой операции остаток тела меняется, поэтому следующий участок процентов считается от нового остатка.

## Досрочка до регулярной даты

Для полноты модели поддерживается и досрочка до очередной даты: начисление до фактической даты, затем погашение процентов и тела, после чего оставшиеся проценты начисляются от нового остатка до очередной даты.

## Пересчёт срока

В режиме `TERM` договорный платёж каждого будущего периода сохраняется. После досрочек график пересчитывается последовательно от нового остатка, поэтому дата закрытия кредита получается как дата фактической последней строки графика.

Для текущего пользовательского сценария с предоставленным договорным графиком и тремя историческими досрочными платежами в даты регулярного платежа контрольный расчёт даёт дату окончания `04.05.2054`, при исходной дате окончания `04.05.2056`.

## Пересчёт платежа

Режим `PAYMENT` оставлен как отдельный сценарий: после досрочного платежа новый платеж рассчитывается на оставшийся срок. Если договор содержит несколько будущих ступеней платежей, точное банковское уменьшение платежа требует уточнённого банковского графика после досрочного погашения; приложение не выдаёт такой режим за точную копию банка.

## Хранение

В таблице `credits`:

- `principal` — первоначальная сумма кредита;
- `annual_rate` — годовая ставка;
- `standard_payment` — базовый/текущий ориентир платежа;
- `term_months` — договорный срок;
- `payment_schedule` — необязательный JSON с реальными ступенями платежей;
- `start_date` — дата выдачи;
- `first_payment_date` — дата первого регулярного платежа;
- `recalculation_mode` — способ изменения условий после досрочки.

В `credit_prepayments` хранится фактическая дата, сумма с копейками и комментарий.

## Важное ограничение

Точный банковский график после досрочного погашения зависит от договора, дня обработки операции, схемы округления и других условий банка. Поэтому Family Hub разделяет: (1) договорный исходный график; (2) собственный расчёт последствий фактических досрочек.


## Contract schedule calibration

For the reference mortgage contract, the payment schedule is 69706.07 for months 1–120, 60202.24 for 121–240, 57734.02 for 241–359, and 70829.31 for month 360. Interest uses actual calendar days with a 365/366 denominator per calendar-year segment. Historical prepayments on a regular due date reduce principal after the regular payment; mid-period prepayments first cover accrued interest from the due date to the prepayment date and then reduce principal.
