# Первый вход в Family Hub

Новый пользователь без семьи видит объяснение пользы и примеры покупок, календаря и расходов. Примеры помечены и не сохраняются. После выбора задачи пользователь явно создаёт семью с редактируемым названием «Моя семья» и переходит к соответствующей форме. Пользователь с приглашением сразу видит его; с существующей семьёй — рабочий экран.

После первого успешного сохранения покупки, события или финансовой операции в текущей сессии предлагается пригласить близкого. Предложение можно закрыть. После перезагрузки оно не восстанавливается. Аналитика активации в этот релиз не включена.

## Telegram

POST `/api/telegram/webhook` принимает личные `/start` и `/help`, проверяет `X-Telegram-Bot-Api-Secret-Token`, возвращает сообщение с кнопкой Mini App. Повтор успешно обработанного update_id игнорируется семь дней. Ошибки Telegram допускают повтор доставки; строгое exactly-once при потере сетевого ответа Telegram не гарантируется.

Для активации после выкладки:

1. Проверить текущую ветку и HEAD сервера. Собрать и пересоздать frontend, backend, backend-nginx, queue и scheduler обычным порядком проекта. Миграций нет. Сохранить зеркало Alpine, применявшееся на сервере.
2. Добавить в `.env.production` непустой случайный `TELEGRAM_WEBHOOK_SECRET` (например, 64 hex-символа), не публиковать его. `TELEGRAM_BOT_TOKEN` должен быть настроен, `APP_URL` — `https://teamportal.ru`.
3. После изменения окружения пересоздать backend; сбросить кеш конфигурации, если он используется.
4. В backend выполнить `php artisan family:setup-telegram --webhook`. Команда настраивает описание, краткое описание, кнопку меню и webhook. Другой существующий webhook не заменяет. Если бот обслуживается отдельным polling-процессом, сначала согласовать его отключение.
5. Проверить `/start` в личном чате бота, открытие Mini App, вход нового пользователя, приглашённого и существующего участника. Секреты и URL Telegram API с токеном не присылать в чат.

Без `--webhook` команда меняет только описание и кнопку меню. В этой разработке реальные настройки Telegram и production не изменялись.

## Проверки

`npm run build` и `npm run test:ui` в frontend. В backend: `vendor/bin/phpunit --filter TelegramWelcomeTest`, затем существующие тесты семей и прав доступа. UI-тесты используют подменённый API: они не подтверждают реальную доставку Telegram.

## Откат

Вернуть предыдущий релиз frontend/backend. Если webhook был впервые включён этим релизом, перед откатом отключить его через Telegram Bot API или вернуть прежнюю интеграцию; не оставлять Telegram направлять запросы на отсутствующий маршрут. Секреты не включать в логи.

## Результат локальной проверки 27.10.2026

Production-сборка frontend успешна. Полный набор из 105 UI-тестов прошёл на Chromium 153 (локальный браузер; в CI используется браузер Playwright). PHP в локальном окружении отсутствует: шесть новых backend-тестов подготовлены, но ещё не запускались. Проверки настоящего бота и production не выполнялись.
